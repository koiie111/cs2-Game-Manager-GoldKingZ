## Implementation

Active name-block index and per-visible-second countdown cache retain tick delivery and two-second name checks. Ordinary human pawn lookup uses a verified controller association; bots/takeover retain the original scan. Debug fields and strings are evaluated only when enabled. Ordered chat rules, weapon settings and auto-clean filters are reused; permissions remain live and deletion order is retained. Literal sound matching retains substring/case behavior.

Map/reload generations guard deferred work; player frame callbacks also check connection identity. Raw-slot disconnect cleanup, cancellable downloads and atomic gamedata replacement protect lifecycle. Config reload reconciles damage listeners. Legacy config conversion preserves ping, blood/headshot, bomb HUD, sound patterns and retention settings. Invalid documents are preserved; normalization creates a pre-upgrade backup. Unsupported enabled AutoSetPlayerLanguage rejects the upgrade explicitly.

## Pilot protocol and limitations

#7 was empty, but LinuxGSM refused to stop because an unrelated Advertisement/PanoramaManager.dll belongs to root. Its GameManager and process were retained. Alternative #34 was empty and used for testing.

#34 normally disables name blocking. Both experiment builds enable BlockNameChanger=1 with no active blocks. Native cvar enforcement and signature updates are disabled in this fixture. This is not its normal production workload. Occupancy is checked before and after windows, without a continuous trace.

Identical temporary Stopwatch/thread-allocation probes wrap OnTick in private experiment copies. Baseline, candidate and repeated baseline have three 30-second dwell windows each, plus command/occupancy-query overhead. Raw duration ticks and allocations are retained; percentiles use nearest rank. Instrumentation overhead is not subtracted. There is no independent full-tick, active-player, timer/native-hook or neighbor-CPU profile. No claim about 150 ms stalls is made.

The probe snapshot precedes final config/connection/lookup fixes; those do not change OnTick. Idle measurements cannot establish full acceptance of the final release. Release binaries contain no probe.

## Re-review, 2026-11-10

The complete optimization plan and existing reports were read from 4ill.ru/main.
The earlier local O5 report records the owner's choice of upstream 2.1.6 as the
fork baseline. This is explicitly an optimization of f7ff9e9, not a backport or a
source identity claim for the installed official 2.1.3. The source mapping for
that older binary remains provisional beyond the recorded official-release hash.

Fixed gaps found in review:
- A rejected config reload used to detach handlers and clear state before parsing.
  Config loading now prepares and validates a candidate before the callback that
  detaches registrations using the old config. Rejection retains the running
  instance and original file; success is reported only after applying the reload.
- Delayed HUD/body/damage callbacks now check map/config and connection lifetime.
  Disconnect cancels that player's timers even when the native controller is no
  longer valid. Completed timers leave BasePlugin.Timers; completed native timer
  handles are not killed again. Damage context expiry checks session-object
  identity and remains independent of either participant disconnecting.
- Name tick/checker/disconnect methods were moved unchanged to a partial source
  file so tests can execute the production code against managed CSS substitutes.
  The two-second checker, mode 1 deadline reset, mode 2 command policy,
  ExecuteOnRoundStart/End and per-tick HTML delivery are retained.

Release version is 2.1.6-perf.2. The previous owner smoke tested perf.1 (c84aca6),
not this release. This review's new timer/config code requires its own canary.
The added lifetime checks add work to timer creation/callbacks; no reduction of
full-path game-thread cost is claimed without the active server profile.
